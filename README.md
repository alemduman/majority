# Что выберешь ты — и что выбирает большинство

Короткие вертикальные ролики (15–17 с, 1080×1920) по данным опросов. Конвейер:
`suggest → research → approve (человек) → script → assets → render → review (человек) → publish (по умолчанию выключено)`.

## Правила данных
- Идём от данных к вопросу; варианты — только те, что были в опросе.
- Каждое число берётся со страницы, которую приложение реально открыло, и автопроверка находит его в сохранённом фрагменте.
  Цифры «из памяти» модели отбрасываются.
- Уровни: **A** — 10+ стран, **B** — 1–9 стран, **C** — нет данных / противоречия / не первоисточник. C в ролик не идёт.
- Охват говорим как есть («42 страны», «США»), никогда «в мире» / «все люди».
- Нет данных → статус `no_data` и 3 похожих вопроса, по которым данные есть.

## Команды
```
python -m majority research "Вопрос?" [--options "A|B"]
python -m majority show <card_id>
python -m majority approve <card_id> [--reject] [--yes]
python -m majority suggest -n 5
python -m majority costs
python -m majority run "Вопрос?"
```
Без `GEMINI_API_KEY` (или с `MAJORITY_MOCK=1`) всё работает на mock-провайдерах без сети и трат.

## GitHub Actions
- **tests** — тесты на mock при каждом пуше.
- **research** — исследование вопросов (секрет `GEMINI_API_KEY`), карточки сохраняются в `output/cards/`, база — `data/majority.sqlite`.
- **approve** — подтверждение/отклонение карточки человеком.

## Этапы
1. ✅ research, карточка факта, approve, тесты
2. ⏳ рендер на mock-ассетах
3. ⏳ платные провайдеры (картинки, голос) с ограничителем бюджета
4. ⏳ публикация (dry-run по умолчанию, TikTok — в черновики)
